# 孵化师 0.9.5 / 秘书 0.1.4 — 登记与交付台账

日期：2026-10-18。Windows x64，原型功能版本。

## 新增与修复

- 通用 Agent 存在登记：目录分析、确认登记、查询已知 Agent，保存身份、版本、编号及位置。同身份重复登记更新位置，相同职业编号不合并不同身份；旧包明确标注永久身份缺口。孵化师与子机都可通过 Agent 登记按钮及模型工具使用。
- 孵化师永久交付台账：记录准备导出、成功打包及 GitHub Release 附件核验历史；工作区失效后仍保留已登记信息。核验本地 EXE 和 GitHub 附件大小/哈希不等于完整安装验收。未记录的旧项目不能自动推断或补造历史。
- 修复话题绑定脚本覆盖已初始化 uahWork、导致 reading observe 的错误。
- 手机服务缺少模型选择时重新读取电脑端实际选择，避免已配置模型仍无法新建话题。本次手机修复的源码已同步；独立手机服务需更新自身程序，不随桌面包自动替换。
- 保留此前在线更新、邮件起草、原生确认发送、附件及抄送密送能力。

## 升级与数据

秘书 0.1.3 使用专用 0.1.4 原位置升级 ZIP；退出秘书，解压升级包到程序目录之外，运行升级.cmd，输入原程序位置和外部备份目录。必须使用实际匹配的原产品和版本，文件被修改时停止。完整备份后只替换程序，保留模型、授权、聊天、知识、技能、工作区与实例资料。升级后沿用原快捷方式。

孵化师 0.9.4 使用专用 0.9.5 原位置升级 ZIP；同样先退出程序、选择原目录和外部备份目录。安装版外部 profile 不被更新包覆盖，升级工具会额外备份并核验该目录。便携版完整程序 ZIP 用于新安装或隔离试用；不要直接覆盖旧数据目录。新装便携版可运行 Create-Shortcuts.cmd 创建桌面和开始菜单入口。既有已发布安装器和标签保留，不覆盖。

新版本源码与资产先发布到私密产品仓库，不自动修改公开稳定签名更新 feed。GitHub Release 上传不等于应用内更新已推送。当前机器的运行实例不在本次制包操作中自动安装。

## 边界

登记只表示知道存在，不自动联网发现、不派工、不授权。双方分别登记后才各自知道对方。旧秘书的名称和版本可识别，但缺少的信息标记未知。

持续改进能力仍是设计规范，尚未实现意见审核、自动修改 9M 或自我升级。GitHub 自动建仓、完整子机安装器自动构建和旧项目历史补录尚未接入。身份清单是本地声明，未提供签名身份认证。
